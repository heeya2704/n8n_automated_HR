# n8n Recruitment Workflows Guide

Two importable workflows. The FastAPI backend is the source of truth for every decision: it applies the **job-specific thresholds** and stores candidate status. n8n only moves data and sends Gmail.

## Workflow 1: Resume Screening (`resume-screening-workflow.json`)

**Triggers:** Gmail inbox (unread emails with a PDF resume) **or** `POST /webhook/resume-screening`

```
Gmail Trigger -> Extract Resume PDF Text --+
Webhook (test) ----------------------------+-> Normalize Candidate Data
  -> Fetch Job Requirements   GET  {BACKEND_URL}/api/jobs/{job_id}
  -> Gemini AI Resume Analysis
  -> Parse Gemini JSON        (throws on bad AI output, so no false rejections)
  -> Screen Candidate         POST {BACKEND_URL}/api/candidates/screen
                              backend decides: score >= job.minimum_resume_score
  -> Route by Decision
       SHORTLISTED -> Send Test Link Email
       REJECTED    -> Send Rejection Email
       DUPLICATE   -> (no email; candidate was already screened)
```

Test the webhook trigger without Gmail:

```bash
curl -X POST http://localhost:5678/webhook/resume-screening \
  -H "Content-Type: application/json" \
  -d '{"candidate_name":"Jane Doe","candidate_email":"jane@example.com","job_id":"python-ml-developer-001","resume_text":"Python developer with FastAPI, SQL, Pandas, NumPy and ML experience"}'
```

## Workflow 2: Test Result (`test-result-workflow.json`)

**Trigger:** `POST /webhook/test-result`. The backend calls it after a candidate submits the online test and it has already set `SELECTED` or `TEST_FAILED`.

```
Webhook -> Parse Payload -> IF Selected?
  true  -> Download Offer Letter PDF   GET  {offer_letter_url}  (binary)
        -> Send Acceptance Email + Offer Letter (Gmail, PDF attached)
        -> Confirm Offer Sent          POST {BACKEND_URL}/api/webhooks/offer-sent
                                       status SELECTED -> OFFER_SENT
  false -> Send Assessment Rejection Email
```

The email subject/body are generated by the backend (`app/services/notifications.py`) from candidate and job data and passed in the payload, so templates live in one place.

If the offer email fails in n8n, `/offer-sent` is never called and the candidate stays **SELECTED · OFFER PENDING** in the HR panel. The failure stays visible and can be retried.

If n8n is **not reachable**, the backend sends the same email itself via Gmail SMTP (`GMAIL_USER` / `GMAIL_APP_PASSWORD`). If that also fails, it writes an `EMAIL_FAILED` workflow log and leaves the status at `SELECTED`.

## Setup

1. Open n8n: `http://localhost:5678`, then go to **Workflows > Import from File** and import both JSON files.
2. Create a **Gmail OAuth2** credential and select it on every Gmail node (the files reference the placeholder `GMAIL_CREDENTIAL_ID`).
3. n8n environment variables used by the workflows:
   - `GEMINI_API_KEY` (required)
   - `GEMINI_MODEL` (optional, default `gemini-3.6-flash`)
   - `BACKEND_URL` (default `http://localhost:8000`; `http://backend:8000` in docker-compose)
   - `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` (so `$env` can be read in expressions)
4. **Activate** both workflows. The backend calls `N8N_TEST_RESULT_WEBHOOK_URL` (default `http://localhost:5678/webhook/test-result`).
